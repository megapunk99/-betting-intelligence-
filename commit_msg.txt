# COMMIT 2 — Fix RuntimeWarning in Discord webhook tests
# ═══════════════════════════════════════════════════════════════════════════
# Files:
#   tests/test_alerts_odds.py   (fixed mock response type)

Fix RuntimeWarning: unawaited coroutine in Discord webhook tests

The TestDiscordWebhook fixture mocked httpx.AsyncClient.post as an
AsyncMock, which returned another AsyncMock.  When send_embed called
resp.raise_for_status() on that mock, it returned an unawaited coroutine
object, generating 12 RuntimeWarning instances across the test class.

Fix: Make client.post return a regular MagicMock response with a
synchronous raise_for_status, matching the real httpx.Response API
where raise_for_status() is synchronous and returns None.

Also add filterwarnings = ["error::RuntimeWarning"] to pyproject.toml's
pytest config so any future RuntimeWarning regression causes test
failures instead of silent warnings.
